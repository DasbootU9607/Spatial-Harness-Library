# Spatial Harness Library

All maintained instructions, interface text, metadata and documentation are English.
Preserve original source bytes and necessary source labels. Keep the official
collections and existing shareable routes intact.

Construction starts through `node tools/construct.cjs start` before task-specific
reference reads. Use its read, note, save, render, verify and finish commands, or
the corresponding shared runtime API. Keep revisions in one run. Resume explicitly;
a sealed run cannot reopen. The exact task and current client session identify a run.
The runtime never invokes or changes a model. See `docs/observability.md`.

Routine publication of completed construction skills and verified tasks to
https://github.com/DasbootU9607/Spatial-Harness-Library and its GitHub Pages site
is authorized as part of task completion. Run `node tools/publish.cjs` with the
finished run and delivered specification; no additional publication request is
needed. Honor explicit local-only and prepare-only requests. Verify before
registration, synchronize origin/main, preserve unrelated work, commit only the
intended files, push to main without force, observe the commit's Pages deployment,
and check the affected URLs. A push is not proof of deployment. Retain prepared
outputs and report concrete blockers instead of blind retries.

Use the shared recorder, schemas, exhibition components and publisher for every
harness. Add domain adapters rather than another recorder or frontend. Domain
skill rules remain authoritative for task correctness. Intermediate drafts,
ephemeral practice and failed or unknown verification are not accepted cases.
Private runs, client bindings, transcripts and command logs must never be committed.
