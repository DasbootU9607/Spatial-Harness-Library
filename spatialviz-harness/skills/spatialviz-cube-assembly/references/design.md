# Cube Assembly production design

## Toolchain

The pinned upstream entry `create_freecad/create_visual_penetration/create_cube_assembly.py` creates the solids in FreeCAD. The two sampled profiles call its random supported-stack builder and connected split routines directly. Its upper reference views and A–C parts are real FreeCAD PNG captures. The authored interface profiles supply coordinates to the same native unit-cube constructor, compounds, visibility loop, camera and screenshot code. For these designed profiles the split and foil definitions come from the authored coordinates.

The host calls the released `visual_penetration_tasks_utils.prepare_composite_image_CubeAssemply` using its original spelling. It crops each FreeCAD image, assigns the three letters, calls `create_composite_image_CubeAssembly` and writes `data.json`. The candidate's final PNG is a byte-for-byte copy of this composition. The text question includes the official stem and the movement contract. Public per-option explanations reflect the actual packing test, including equal-volume candidates where the original writer's generic missing-cube text does not apply.

## Native adaptations and evidence

The host exposes the local document to the archive's cube helper. Before each capture it lets FreeCAD's isometric animation settle, selects orthographic projection and leaves a framing margin. Changed-view candidates additionally use recorded world-space yaw offsets. The native document is saved before closure. Each occupied cell is read from the position and extent of a unit OCCT solid. The DejaVu Sans Bold request resolves to the matching bundled font.

The generation seed chooses the native stack and official option order. For the local-mutation pair the second composition uses an explicitly recorded second shuffle seed, so exchanging the correct endpoint leaves the displayed A/B/C shapes in the same positions. Only the target's single riser moves. The camera settings, original archive answer, raw and cropped panel fingerprints, native-model fingerprint and final geometry travel with the task.

Raw captures and the FCStd stay in the job's `raw/VisualPenetration/CubeAssembly` tree. The `composed` tree retains the officially cropped, labeled inputs and `data.json`. The [source audit](official-audit.md) separates released evidence from the authored camera and rigid-motion rules.
