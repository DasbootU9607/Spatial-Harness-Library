# Environment and construction parameters

Use Node 20+, host Python with Pillow, NumPy, OpenCV and PyMuPDF, and the real FreeCAD GUI with Part and TechDraw. Tested with FreeCAD 1.0.2, Pillow 11.3, NumPy 2.2.6, OpenCV 5 and PyMuPDF 1.27.2.3. The shared rotation runtime resolves `SPATIALVIZ_FREECAD`, the library's private FreeCAD runtime configuration or PATH. `SPATIALVIZ_PYTHON` selects the host interpreter. The GUI uses its bundled Python and A4 landscape blank template. Keep Python assertions enabled. Missing GUI modules, template, PDF views or a failed verifier require a new attempt after diagnosis.

## Inputs

Supply a safe integer seed and a JSON parameter file.

- **Cubes.** `{"branch":"cubes","heightMap":[[3,1,0],[1,1,1],[1,0,0]]}`. Rows increase in +Y and columns in +X. Positive heights fill all integer Z from zero. Optional `red` and `alternativeRed` are arrays of distinct occupied [x,y,z] coordinates. The latter decorates the separate foil model. Omit either list for seeded coloring. Omit the map for seeded proposals. The local bound is eight cells per axis. Overlap, unsupported cubes and disconnected components are rejected. A gray majority preserves the source wording. Individual cubes may be partly or fully occluded. Each accepted task retains both colored coordinate lists.
- **CAD bores.** `{"branch":"cad","mechanism":"bores","size":[48,28,14],"holes":[[13,8,3],[34,19,5]],"given":"Front","target":"Top"}`. Size gives the base dimensions in millimeters. Each hole is [x,y,radius] measured from the front-left corner. Both holes pass through the plate. The two cylinders must clear one another and the plate boundary.
- **CAD step.** `{"branch":"cad","mechanism":"step","size":[44,30,16],"bossSize":[19,16,12],"given":"Top","target":"Front"}`. The boss meets the back and left boundaries. Omit dimensions, features or either view to use the seeded proposal. The base accepts integer dimensions from 10 to 80 mm. Use only view pairs listed in the coverage table. A pair or seed with too few distinct graphical distractors can be rejected. Change the seed, feature placement, dimensions or view pair and retain the original recorder evidence.

## Upstream integration

The projection adapter is in `tools/observatory/adapters/official-projection.cjs`. The controller, GUI macro entry and independent solver are in `spatialviz-harness/official-projection`. Its `source.json` identifies the MIT license, archive SHA-256, upstream commit and digest of each original file. Verify these digests before applying the in-memory source substitutions. Original files are in `spatialviz-harness/vendor/SpatialViz-Bench-c27f9111a267`. Preserve this directory's byte-level Git attributes.

- `create_cubes_3view_projection.py` creates the unit boxes and duplicate document objects, and saves the original isometric, front, top, left and right views plus the two recolored side views. The local driver supplies validated placements and object materials. At each official save boundary it waits for the orthographic camera to settle, fits to white paper and records the basis and physical model.
- CAD geometry starts with a local OpenCASCADE box and a parameterized fuse or pair of cylinder cuts. `create_cad_3view_projection.py` reimports the new STEP, gathers properties, filters it, constructs the first-angle TechDraw group, exports the PDF and renders the isometric. The local hook records the actual imported face triangulations and BRep. The public evidence includes a metadata-stripped copy of the drawing PDF.
- `generate_data.py` actually dispatches `prepare_composite_image_Cubes3View` or `prepare_composite_image_CAD`. The upstream utilities crop the source images, generate or assign distractors, shuffle labels, lay out and label both rows and write the official answer annotation. The exact patched source hashes and reasons appear in each task. Local substitutions select the new folder, deterministic ordering, requested CAD views and packaged font. They correct Windows separators, dotted file paths, failed PDF crop detection, incorrect reference resize arguments and fallback label accounting. PDF cropping uses connected dark outlines and removes light-gray paper fill before generating distractors. The final learner explanations are derived from visible differences.
- Use `inventory.py --sheets DIRECTORY` with host Python to regenerate the inventory and the ten review sheets from the original question collection. Do this within a recorder run when constructing a case.

## Acceptance and limits

For cubes the solver max-selects the nearest cube independently on each projection ray. To reject a misleading foil, enumerate supported column heights constrained by the given footprint and front/side skylines. At each feasible height assignment unify the visible color of every ray terminating on the same cube. Any consistent assignment disqualifies the foil. Ignoring the isometric and face-connectivity constraints in this search makes rejection conservative. A search beyond 150,000 height assignments fails closed. Seeded proposal selection has 120 attempts.

For CAD, rasterize triangles of the reimported solid into a 320-square depth buffer. Depth interpolation selects the closest face. Boundaries between visible face IDs predict the silhouette and internal lines without using TechDraw, filenames or option labels. Compare strokes bidirectionally after isotropic scale and translation alignment. Maximum displacement below 4.5 normalized pixels counts as matching. A foil must differ by more than 8 pixels. Check all three PDF views and the isometric. Through-bores and the single corner step are covered by the construction statement in the question. Do not use the verifier for unrestricted STEP models or hidden-line interpretation.

The image audit compares cube face interiors to gray (174,181,189) and red (255,0,0), including the isometric. It checks camera orientation, visibility, edges, crop replay and all labels. CAD checks the PDF crops, visible mesh boundaries, option edits and reference resize. A separate Pillow reconstruction must agree pixel-for-pixel with the final official compositor. Inspect the exact candidate PNG before a positive visual review. Render, verify and review revised candidates again. Use the existing shared publisher for registration and deployment. Each sample run records its own process. Concurrent passive usage windows can overlap.
