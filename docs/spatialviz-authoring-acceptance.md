## Tool and case audit

The older authoring checkout also contains unmerged 3D Rotation height-map input and a Three-View CAD operation-list branch. The baseline's 3D Rotation adapter takes explicit cube coordinates; its Three-View adapter accepts stack height maps and the step/bore CAD branches. The guide exposes the confirmed release interfaces. The local experiments were preserved separately and have no release acceptance claim here.

- Rotation, projection and cube folding use the pinned SpatialViz-Bench FreeCAD scripts and corresponding official compositors. Raw CAD views, generated panels and saved final figures are present in the recorded native runs. The projection CAD branch uses TechDraw. The harness independently checks coordinates, projected edges, visible pixels and answer relations as applicable.
- Paper Folding uses the upstream Matplotlib/Pillow pipeline. Arrow Movement uses the upstream movement model and Matplotlib; Block Movement uses the upstream model and FreeCAD. The three corrected guided runs reproduced the archived final PNG bytes. Their parent candidates deliberately failed the new declared-reasoning checks.
- Cross-Sections, Cube Assembly and Cube Counting retain the separate modeling/slicing, packing and TechDraw/height-map pipelines. Each executed the pinned official entry, FreeCAD and compositor and produced native documents and the final plate. The archived catalog pairs all 26 previous local-rendered cases with their 12, 6 and 8 native replacements. The native counting and assembly replays reproduced the figure bytes. A fresh section render had small raster differences; the geometry, plate and visual review passed.
- Mechanical System uses the library's own FreeCAD construction, recorded model reopen, measured interfaces and final question plate. The hoist replay reopened the model and measured 24 interfaces/checks; the final render was inspected again. The 43 older schematic records remain accessible. They have no one-to-one replacement map to the four native assemblies.
- The archived 2D dots case `1ffc3acd58a1ff99886e687d` already points to its official replacement `f3e2bb897cc215f0aba5f0a0`. Both dimensions also retain historical JavaScript/SVG cases outside the current exhibition. The geometric corner-shortcut case remains valid for its general rotation question. Only the local stronger-goal test required a recomposed figure. No public example, old record, or native source revision was rewritten by this iteration.

Each forward run went through reference selection, actual original-image inspection, a four-sentence design, native generation, rendering, independent verification, visual review and local finish. The five rotation/projection/cube-folding plates were also reverified via the final shared verifier routing. Candidate artifacts and original observations are private run evidence. The reusable [protocol](../tools/observatory/tests/authoring.test.cjs), [rotation and folding](../tools/observatory/tests/rotation-folding-reasoning.test.cjs), [solids and mechanisms](../tools/observatory/tests/solids-reasoning.test.cjs), and [folding and movement](../tools/observatory/tests/motion-reasoning.test.cjs) regressions exercise success and failure with named archived cases. These checks test construction, evidence and repair. Model-to-model performance and human readability scores require separate experiments.
